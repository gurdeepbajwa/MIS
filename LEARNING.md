# Learning Preferences

This note records durable preferences for how explanations and study support should be tailored.

## Current Preferences

- Use the saved [personal-writing-style skill](/Users/deepbajwa/.codex/skills/personal-writing-style/SKILL.md) for prose work. The user wants an evolving writing profile: learn from their own writing and explicit feedback, save stable preferences, and refine them over time. Keep the detailed profile in the skill rather than duplicating it here. Start with plain, natural but academic language, clear claims followed by findings and meaning, and no repeated points; adapt to the audience and current request.
- For assignment writing, provide section-level dot points, high-level direction, source suggestions, and short verified quotes with locations. Let the user write the prose; do not draft full sections unless asked.
- The user learns best when technical notes are complemented with simple, intuitive explanations.
- When introducing a course term, framework, method, or exam instruction, explain its purpose in plain language before or alongside the formal wording.
- Emphasise why a concept exists, why it happens in practice, and how it fits into the bigger consulting or business-analysis workflow.
- The user learns well through mental model building and systems thinking: explain how knowledge fits together from start to end, including the sequence, dependencies, purpose, and final outcome.
- When teaching a framework, process, or complex topic, first give a simple start-to-finish map before drilling into individual parts.
- The user is also a visual learner. Use visual models, diagrams, tables, flows, or structured maps where useful to make relationships easier to see.
- The user still wants to memorise technical details when required, especially for exams. Use visual models as retrieval aids that help anchor precise terms, definitions, criteria, and step sequences rather than replacing them.
- Use simple translations of formal terms when helpful. For example, "initial engagement plan" can be explained as "what the consultant will do first with the client".
- Keep the intuitive explanation connected to the course source so the user can still write precise academic or exam-ready answers.
- The user wants flashcard-style exam study support for PISC and DBA: use short active-recall prompts, concise backs, distinction cards, trigger-recognition cards, and exam-use cues.
- For course study sessions, use an adaptive flow: introduce one topic with a simple map and example, discuss it briefly, then ask one question at a time. Move from short answers to multiple choice and applied cases, raising or lowering the level based on the user's answers.
- The user prefers a video as the first pass on a new topic, followed by detailed text that supplies a large amount of linked content.
- The user finds real company incidents and case studies more engaging than abstract risk claims. Use them to explain why a concept matters and connect it to real consequences, while keeping formal course terms precise.
- The user often needs a few days for a large amount of new content to settle while doing other tasks. Do not treat a pause as lost progress. On return, begin with recall and application, then raise the expected level if retention supports it.
- Plan study in waves where useful: video entry, text expansion, a break for the ideas to settle, then delayed recall and harder application.
- Randomise multiple-choice answer positions and matching-list order. Avoid obvious sequences such as `A–1, B–2, C–3, D–4`, since they can make the user second-guess correct knowledge. Do not treat an answer affected by a clear question-order pattern as firm evidence of a concept gap; retest with a well-randomised item.
- Do not overdrill one study topic after the user has shown sound application. Mark it for delayed review and move to the next area. Use focused follow-up only for a real concept gap, and keep the user aware of the current topic and what comes next.
- During a live tutorial, treat short topic fragments as capture notes. Log them under the current week's tutorial note, mark them for later expansion, and keep the chat response short unless the user asks for an explanation.
